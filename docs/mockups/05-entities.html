05 · 实体剪影标本页（植物 / 僵尸）

本页回答的是「植物和僵尸还没有 UI，怎么定」这件事。给出的不是美术，是形状语言表 + 尺寸账 + 可直接复用的 M4 生图 prompt 骨架。 原型 02 / 03 页场上的色块已经换成这里的 SVG 剪影（entities.js）。

红线（§2）：这些轮廓是自写的，不参考、不描摹、不借用任何商业游戏形象；命名也不沿用原版角色名—— UI 上出现的「豌豆投手」「中性苗木」是本项目自己的名字。§9 音效用 Kenney CC0，但明确「不借植物形状」， 即音效包里的叶子/花朵素材同样不进本项目。

1. 形状语言表：功能写在轮廓里，不写在颜色里

规则：把图转成纯黑剪影，仍然能认出它干什么，才算形状过关。颜色只负责阵营（植物冷绿/黄绿，僵尸暖灰紫）， 不负责「这是射手还是坚果」——因为色觉差异和低龄玩家不会靠颜色做战术判断。

场上 112px 预览slot轮廓特征（形状语言）孩子怎么读它 / M0 落点

朝向约定（唯一的「方向即信息」例外）：只有 shooter 带朝向，管口指向 = 攻击方向 = 面朝僵尸。 producer / defense 刻意做成旋转对称，避免「它朝哪边就打哪边」的误读——草坪是一维推进（§5），射手实际打整条 lane。

2. 尺寸账：为什么是 88 而不是 §9 写的 96

竖向预算高度说明
HUD50阳光 / 波次 / 时钟 / 自证角标

合计 ≤ 720（D14）H ≤ 8896 会让总高变成 50 + 480 + 230 = 760，超画幅 40px → 要么砍掉一行草坪，要么把抽屉压到 190（字母块会掉到 30px 以下，低龄不可读）。所以 §9 的场上尺寸必须改成 88。

横向不是瓶颈：草坪 1200 宽 ÷ 9 列 = 120px 格宽，88 素材横竖都放得下，左右各留 16px 呼吸。 最小可玩 960×600 时 Scale.FIT 等比缩到 0.75，场上素材实际约 66 CSS px——这是 88 的下限依据，不能再往下让。

同一份轮廓在三档尺寸下的样子（§9：场上 / 卡牌 / 图鉴）

§9 的三档命名 plant_{id}_{s,c,l}.png 保持不变，只把场上档从 96 改 88。 三档共用同一轮廓描述，缩放不重画——这也是「状态用叠加层不用独立素材」的前置条件。

3. 深色描边是被测出来的，不是风格偏好

草坪底色是绿条纹（浅 #dfe7dd / 深 #d3dcd1）。 下面按 WCAG 相对亮度算法实测，不是估算——同一算法可以直接搬进构建期脚本。

部位fillvs 浅草坪vs 深草坪 描边vs 浅草坪vs 深草坪判定（描边阈値 2.0）

结论不是「描边更好看」，是「fill 单独放草坪上基本不存在」：最差的一条（产阳光的果苞 #f0d06a vs 深草坪）只有 1.07—— 也就是不描边的话，88px 下那块黄色会和草坪融成一片。加了描边后最差也到 2.22，全部达标。 因此规则定为：每个部位色块必须配一个深色描边，且描边对深草坪的对比度 ≥ 2.0；fill 本身的对比度不作要求（fill 只负责区分 slot 家族，不负责边缘）。 描边色由该 slot 自己的深色决定，不用统一黑：统一黑会和僵尸的暖灰抢注意力，也会让图鉴页白底上的图显得硬。
建议回写文档：把这条阈值并进 §11-4 构建期校验（素材色板 → 与草坪底色实测），换色批次立刻能被抓出来；果苞 #b98a22 是最接近临界的一条，M4 调色时先看它。

4. 僵尸四档：差异只落在「体积出现在哪里」

僵尸hpspeed形状差异（剪影可辨）为什么这样够

首批就是 §7 的 4 种，不带 Boss（§1 非目标）。四种共用同一具身体，只有头部/肩部附件不同—— M4 生图时可以先出一张基准，再用图生图加附件，批次一致性成本最低（D22）。

5. 状态用叠加层，不新画素材

素材量账：8 株 × 3 档 = 24 张是基线。若「受击裂纹 3 档」「强化」「休眠」都各画一套，会膨胀到 24 × 4 = 96 张。 现在用叠加层：裂纹是 1 张可裁切的 SVG 路径（0/1/2/3 档只改 path 段数），强化是 CSS 光环，休眠是 filter: grayscale(1) + 虚线罩。 额外素材 = 0 张。这也是 D22「三档尺寸」能够成立的原因。
