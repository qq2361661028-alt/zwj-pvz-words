拼词塔防教学版 · M0 页面原型

依据 docs/superpowers/specs/2026-11-07-pvz-word-spelling-tower-defense-design.md §15 的 M0 范围制作： 1 关 · 3 株植物 · 8 个词 · 纯色块代替美术 · 无语音。 双击任一页面即可离线打开，不需要 npm / Vite / 构建。

对外名称与 UI 文案不出现原版字样（§2）。01–04 是 wireframe；05 给的是形状语言而非最终美术—— 剪影定「能不能一眼读出功能」，ImageGen 定「好不好看」，两件事分开拍板。

复核时请重点拍板的三处

  1. 面板显示音标是否会泄漏拼写：/ˈsʌnflaʊə/ 对高年级孩子约等于给答案。文档未规定面板显示什么词形信息，原型按「只显示中文 + 音标 + 词长 + 已填字母」实现，需你确认。
  2. 10 字母词该不该进 M0：peashooter 触发了 §11-4 词长分布告警（Unit 3 里 ≥8 字母占 67%），也是 dormant 降级的靶子。M0 只有 8 个词，一个长词就够把关卡拖成长度测试。
  3. 场上素材 96px 必须改 88px（§9）：竖向账是死的——HUD 50 + 草坪 5×88 + 抽屉 230 = 720；用 96 就是 50 + 480 + 230 = 760，超画幅 40px（D14）。 三条出路：改 88 ／ 砍一行草坪（违反 §5）／把抽屉压到 190（字母块掉到 30px 以下，低龄不可读）。原型按 88 实现，推导与实测在 05 第 2 节。
    同页还挂着两个素材侧待拍板项：special 的形状位要不要在 M0 定死、以及「8 株只需 4 套轮廓 + 1 个变体」这个复用口径你认不认。

上一轮的第三项已闭环，不用再拍：「§6.2 每行最多 12 块在 1280 画幅里放不下」的根因是填词 UI 挤在 480px 右侧面板里。 现在改为草坪全宽 + 底部 1220px 抽屉，字母块区实测 1046px 宽 ÷ 块距 42px = 每行 25 块（不是估算，03 页可复现）； 而 §4.4 词长 ≤10 + §6.2 干扰 ≤6 → 任何合法词最多 16 块。12 块的约束自动满足，§6.2 无需改动，只是布局 token 变了。
顺带跑出来的第二条：同一组数字让 §6.5 的「词过长致布局溢出」降级分支在当前布局里永不可达（03 页 E 场景已改为强制状态演示）—— 这条要回写文档，标成「防御性分支，M0–M4 不测」，否则它会以「已实现的降级」留在代码里却从没被执行过。

原型跑出来的一个设计缺口（建议回写进文档）

D16 + D7 叠加会起步死锁。 D16 规定阳光只由已激活的 producer 产出（起始 75，producer 每 12s 产 25）；D7 又强制只能填最左那张。 于是：若词序的第一张卡映射到 cost > 75 的非 producer 植物（例如 peashooter 100），玩家既无法跳过它，也没有任何阳光来源—— 填得再对也种不下去，且这不是数值调平问题，是可达性问题。
原型里已把它固化成校验：01 页门禁表最后一行「反例：peashooter 打头 → 死锁」，02 的词序已改为 sunflower(→sprout 50) 打头。
建议：§11-4 构建期校验增加一条「decks 顺序必须满足：首卡 cost ≤ 起始阳光，且前 2 张内含一个 cost ≤ 起始阳光的 producer」； §13 可加一条 O6（或直接把起始阳光提到 100 / 给 peashooter 定价 ≤ 75）。

文件清单：shared.css（token + 组件 + 尺寸账注释）· shared.js（夹具 + submit/干扰字母/校验，可单测的部分）· entities.js（MockShapes：12 个 SVG 剪影 + 状态叠加层）· panel.js（抽屉渲染）· 5 个页面。 这些是原型不是实现代码——真实实现里 shared.js 对应 src/rules/， 且必须通过 ESLint no-restricted-imports 保证不含 phaser 与 DOM（D3）。
